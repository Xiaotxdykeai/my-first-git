# 第四章思维导图

## 一、串的基本概念

### 1. 定义
- **串（String）** ：由零个或多个字符组成的**有限序列**
- 串是一种**特殊的线性表**——数据元素限定为**字符**

### 2. 重要术语

| 术语 | 含义 |
|------|------|
| **串长** | 串中字符的个数 |
| **空串** | 长度为 0 的串，记作 `''` |
| **空格串** | 由一个或多个空格字符组成的串（长度 > 0） |
| **子串** | 串中任意**连续**字符组成的子序列 |
| **主串** | 包含子串的那个串 |
| **字符位置** | 字符在串中的序号，**从 1 开始** |
| **子串位置** | 子串第一个字符在主串中的位置 |
| **串比较** | 从第一个字符开始比较 ASCII / Unicode 编码值；前缀相同则**长度更长**的串更大 |

### 3. 串 vs 线性表

| 对比项 | 线性表 | 串 |
|--------|--------|-----|
| 数据元素类型 | 任意 | **字符** |
| 基本操作对象 | 单个元素 | 通常以**子串**为单位 |


## 二、串的存储结构

### 1. 顺序存储

| 实现方式 | 特点 | 优点 | 缺点 |
|----------|------|------|------|
| **定长顺序存储**（静态数组） | 预定义最大长度，`length` 记录实际长度 | 随机存取 | 容量固定，无法扩展 |
| **堆分配存储**（动态数组） | 用 `malloc` / `free` 动态管理 | 容量可扩展 | 需手动管理内存 |

**王道教材默认方案**：
- 字符从 `ch[1]` 开始存放，`ch[0]` 弃用
- 单独的 `int length` 记录串长
- 避免了下标转换（位序 = 数组下标），且支持更长串

### 2. 链式存储

| 存储方式 | 存储密度 | 特点 |
|----------|---------|------|
| 每个结点存 1 个字符 | 低（指针占 4B，字符占 1B） | 指针开销大 |
| 每个结点存多个字符 | 高 | 需用 `#` 或 `\0` 填充不满的结点 |

> 链式存储**不支持随机存取**，插入/删除方便但查找需遍历。


## 三、串的基本操作

| 操作 | 函数接口 | 功能 |
|------|---------|------|
| 赋值 | `StrAssign(&T, chars)` | 将字符串常量赋给 T |
| 复制 | `StrCopy(&T, S)` | 将 S 复制给 T |
| 判空 | `StrEmpty(S)` | 判断是否为空串 |
| 求长 | `StrLength(S)` | 返回串的长度 |
| 清空 | `ClearString(&S)` | 逻辑清空（`length = 0`） |
| 销毁 | `DestroyString(&S)` | 回收存储空间 |
| 串联接 | `Concat(&T, S1, S2)` | 拼接两个串 |
| **求子串** | `SubString(&Sub, S, pos, len)` | 从 S 中取子串 |
| **串比较** | `StrCompare(S, T)` | 比较两个串的大小 |
| **定位（模式匹配）** | `Index(S, T)` | 返回 T 在 S 中第一次出现的位置 |


## 四、朴素模式匹配算法

### 1. 基本思想
- 主串长度 n，模式串长度 m
- 依次检查主串中所有长度为 m 的子串（共 `n - m + 1` 个）
- 逐个字符比较，找到第一个完全匹配的子串则返回其起始位置
- 若所有子串都不匹配，返回 0

### 2. 实现要点
- 失配时：主串指针 `i = i - j + 2`（回溯到下一个子串起点），模式串指针 `j = 1`
- 匹配成功条件：`j > m`，返回 `i - m`

### 3. 时间复杂度
- **最好**：O(1)（第一个字符就失配）
- **最坏**：**O(n × m)**（如主串 `"aaaaab"`，模式串 `"aaab"`，每次都在最后一位失配）


## 五、KMP 算法

### 1. 核心思想
> **主串指针 i 不回溯**，仅模式串指针 j 适当回退，跳过不可能匹配的子串。

- 失配时 j 回退到 `next[j]`
- 回退位置**仅由模式串本身决定**，与主串无关

### 2. `next` 数组的手算

**固定结论**：
- `next[1] = 0`（特殊标记，配合 `j == 0` 逻辑让主串指针后移）
- `next[2] = 1`（任何模式串都成立）

**通用求法**（`j ≥ 3`）：
> `next[j]` = 由前 `j-1` 个字符组成的子串的**最长相等前后缀长度 + 1**

**手算技巧**——滑动对齐法：
1. 在失配位置前画分界线
2. 将模式串向右移动，观察前缀能否与已知后缀对齐
3. 找到第一个能对齐的位置，其下标即为 `next[j]`
4. 若完全越过分界线仍无法对齐，则 `next[j] = 1`

### 3. `nextval` 数组（KMP 优化）

**优化动机**：若 `P[j] == P[next[j]]`，则回退到 `next[j]` 后仍会失配，应继续回退。

**手算规则**：
- `nextval[1] = 0`
- 对 `j ≥ 2`：
  - 若 `P[j] == P[next[j]]`，则 `nextval[j] = nextval[next[j]]`
  - 否则 `nextval[j] = next[j]`

### 4. KMP 匹配过程

```c
i = 1, j = 1;
while (i <= S.length && j <= T.length) {
    if (j == 0 || S.ch[i] == T.ch[j]) {  // ① j==0 处理首字符失配
        ++i; ++j;
    } else {
        j = next[j];  // ② i 不变，仅 j 回退
    }
}
if (j > T.length) return i - T.length;
else return 0;
```

### 5. 时间复杂度
- 求 `next` 数组：O(m)
- 匹配过程：O(n)
- **整体：O(n + m)**


## 六、核心对比总结

| 算法 | 主串指针 i | 时间复杂度 | 核心特点 |
|------|-----------|-----------|----------|
| 朴素匹配 | 回溯 | O(n × m) | 简单，但重复比较多 |
| KMP | **不回溯** | **O(n + m)** | 利用 `next` 数组跳过无效比较 |
| KMP 优化版 | 不回溯 | O(n + m) | 用 `nextval` 进一步减少冗余 |


## 七、易错点清单

| 易错点 | 正确理解 |
|--------|----------|
| 串中字符位置从 0 开始 | 串中位序**从 1 开始**（与线性表一致） |
| 空格串 = 空串 | 空格串长度 > 0，空串长度为 0 |
| `next[1] = 1` | `next[1] = 0` 是固定结论，用于触发 `j==0` 处理 |
| KMP 中 i 不回溯 | i 始终保持递增，这是 KMP 的核心优势 |
| 子串与模式串混淆 | 子串**一定存在**于主串中；模式串**不一定**能匹配上 |
| 串比较时只比较到较短串结尾 | 若前缀全部相同，**长度更长**的串更大 |


## 八、记忆口诀

- **朴素匹配**：逐个试，失败就从头。
- **KMP 思想**：主串 i 不走回头路，模式串 j 按 `next` 退。
- **求 `next`**：看前串，找最长相等前后缀，长度加一。
- **求 `nextval`**：若回退字符还相同，继续往前跳。
